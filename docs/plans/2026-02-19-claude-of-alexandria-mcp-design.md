# Design: Claude of Alexandria MCP Server

**Date:** 2026-02-19
**Status:** Approved
**Author:** Dawid (davebream)

---

## Problem

The `biblical-segmentation` skill relies on four Python scripts to query 139MB of reference data (Levinsohn discourse features, Masoretic paragraph markers, vocabulary frequencies, morphological parsing). These scripts require Claude Code's Bash tool to execute.

Claude Desktop users cannot run Python scripts. Additionally, the Claude Desktop skill upload has a 30MB uncompressed ZIP limit. This means Desktop users get only the methodology (SKILL.md) with none of the data-driven scholarly analysis that makes the skill valuable.

The ZIP size is a secondary concern. The primary problem is that **Desktop users have no way to access the reference data at all**.

## Solution

Replace the four Python parser scripts with a single TypeScript MCP server: **claude-of-alexandria-mcp**.

The server compiles all reference data (JSON/YAML) into a SQLite database at build time and exposes four query tools over the MCP protocol. Both Claude Code and Claude Desktop can call MCP tools, giving both platforms full functionality.

## Architecture

### MCP Server

Single TypeScript package published to npm as `claude-of-alexandria-mcp`.

```
servers/claude-of-alexandria-mcp/
├── src/
│   ├── index.ts              # MCP server entry point (stdio transport)
│   ├── tools/
│   │   ├── discourse.ts      # query_discourse_features (replaces levinsohn_parser.py)
│   │   ├── paragraphs.ts     # query_paragraph_breaks (replaces sefaria_paragraphs.py)
│   │   ├── vocabulary.ts     # query_vocabulary (replaces vocabulary_parser.py)
│   │   └── morphology.ts     # query_morphology (replaces morphology_parser.py)
│   └── db/
│       └── query.ts          # SQLite query layer (better-sqlite3)
├── scripts/
│   └── build-db.ts           # Convert JSON/YAML source data → SQLite
├── data/
│   └── biblical.sqlite       # Build artifact (~40MB estimate), shipped with package
├── package.json
└── tsconfig.json
```

### Data Pipeline

```
reference/levinsohn/*.json    ─┐
reference/masoretic/*.json    ─┤
reference/vocabulary/**/*     ─┼── build-db.ts ──→ biblical.sqlite
reference/morphology/**/*     ─┘
```

The raw JSON/YAML files remain in the repository as source-of-truth. The SQLite database is a build artifact generated by `build-db.ts`. The build script reads from the existing reference data paths — no data transformation beyond loading into tables.

### SQLite Schema

```sql
-- Levinsohn NT discourse features (from reference/levinsohn/*.json)
CREATE TABLE discourse_features (
  id INTEGER PRIMARY KEY,
  book TEXT NOT NULL,
  chapter INTEGER NOT NULL,
  verse INTEGER NOT NULL,
  feature TEXT NOT NULL,        -- 'historical_present', 'left_dislocation', etc.
  word TEXT,                     -- Greek word form
  description TEXT
);
CREATE INDEX idx_discourse_book ON discourse_features(book, chapter, verse);

-- Masoretic paragraph markers (from reference/masoretic/*.json)
CREATE TABLE paragraph_markers (
  id INTEGER PRIMARY KEY,
  book TEXT NOT NULL,
  chapter INTEGER NOT NULL,
  verse INTEGER NOT NULL,
  marker_type TEXT NOT NULL      -- 'petuchah' or 'setumah'
);
CREATE INDEX idx_markers_book ON paragraph_markers(book, chapter, verse);

-- Vocabulary frequencies (from reference/vocabulary/**/*.json + YAML)
CREATE TABLE vocabulary (
  id INTEGER PRIMARY KEY,
  book TEXT NOT NULL,
  testament TEXT NOT NULL,       -- 'nt' or 'ot'
  chapter INTEGER NOT NULL,
  lemma TEXT NOT NULL,
  frequency INTEGER NOT NULL
);
CREATE INDEX idx_vocab_book_lemma ON vocabulary(book, lemma);

-- Morphological parsing (from reference/morphology/**/*.json)
CREATE TABLE morphology (
  id INTEGER PRIMARY KEY,
  book TEXT NOT NULL,
  testament TEXT NOT NULL,
  chapter INTEGER NOT NULL,
  verse INTEGER NOT NULL,
  word_position INTEGER NOT NULL,
  text TEXT NOT NULL,
  lemma TEXT NOT NULL,
  pos TEXT NOT NULL,              -- 'noun', 'verb', etc.
  parsing TEXT                    -- JSON string: case, number, gender, tense, etc.
);
CREATE INDEX idx_morph_range ON morphology(book, chapter, verse);
```

### Lemma & Theme Metadata

Thematic keyword mappings and clustering thresholds from `vocabulary_parser.py` are compiled into an additional metadata table or hardcoded in the vocabulary tool:

```sql
CREATE TABLE thematic_keywords (
  theme TEXT NOT NULL,
  lemma TEXT NOT NULL,
  testament TEXT NOT NULL
);
```

Predefined themes: joy, faith, love, righteousness, covenant, blessing, holy.

Clustering threshold: 60% concentration (matching current `CLUSTERING_THRESHOLD = 0.6`).

## Tool Interfaces

### query_discourse_features

Replaces `levinsohn_parser.py`.

**Input:**
```json
{
  "book": "Mark",
  "features": ["historical_present", "left_dislocation"],
  "chapter_range": "1-5"
}
```

- `book` (required): NT book name
- `features` (optional): filter to specific features; default: all segmentation-relevant features
- `chapter_range` (optional): "start-end" chapter filter

**Output:**
```json
{
  "book": "Mark",
  "features": {
    "historical_present": [
      { "chapter": 1, "verse": 12, "word": "ἐκβάλλει", "description": "Scene transition to wilderness" }
    ]
  },
  "summary": { "historical_present": 42, "left_dislocation": 7 }
}
```

### query_paragraph_breaks

Replaces `sefaria_paragraphs.py`.

**Input:**
```json
{
  "book": "Genesis",
  "chapter_range": "37-50"
}
```

- `book` (required): OT book name
- `chapter_range` (optional): chapter filter

**Output:**
```json
{
  "book": "Genesis",
  "markers": [
    { "chapter": 37, "verse": 2, "type": "petuchah" },
    { "chapter": 37, "verse": 5, "type": "setumah" }
  ],
  "summary": { "petuchot": 12, "setumot": 18, "total": 30 }
}
```

### query_vocabulary

Replaces `vocabulary_parser.py`.

**Input:**
```json
{
  "book": "Philippians",
  "testament": "nt",
  "theme": "joy",
  "check_clustering": true
}
```

- `book` (required): book name
- `testament` (optional): "nt" or "ot", default "nt"
- `theme` (optional): thematic keyword to filter by
- `check_clustering` (optional): check for notable vocabulary clustering

**Output:**
```json
{
  "book": "Philippians",
  "testament": "nt",
  "lemmas": {
    "χαίρω": { "total": 9, "by_chapter": { "1": 3, "2": 2, "3": 1, "4": 3 } }
  },
  "clustering": {
    "has_clustering": true,
    "notable_count": 2,
    "clusters": [
      { "lemma": "χαίρω", "concentration": 0.67, "chapter_range": "1-2" }
    ]
  },
  "thematic_matches": [
    { "lemma": "χαίρω", "total": 9, "by_chapter": { "1": 3, "2": 2, "3": 1, "4": 3 } },
    { "lemma": "χαρά", "total": 5, "by_chapter": { "1": 2, "2": 1, "4": 2 } }
  ]
}
```

### query_morphology

Replaces `morphology_parser.py`.

**Input:**
```json
{
  "book": "Philippians",
  "range": "1:1-1:11",
  "testament": "nt",
  "pos_filter": "verb",
  "word_filter": "ἐναρξάμενος"
}
```

- `book` (required): book name
- `range` (required): verse range "chapter:verse-chapter:verse" or single "chapter:verse"
- `testament` (optional): "nt" or "ot", default "nt"
- `pos_filter` (optional): filter by part of speech
- `word_filter` (optional): filter by word form or lemma

**Output:**
```json
{
  "book": "Philippians",
  "range": "1:1-1:11",
  "words": [
    {
      "verse": "1:6",
      "text": "ἐναρξάμενος",
      "lemma": "ἐνάρχομαι",
      "pos": "verb",
      "parsing": { "tense": "aorist", "voice": "middle", "mood": "participle", "case": "nominative", "number": "singular", "gender": "masculine" }
    }
  ],
  "summary": { "total_words": 1, "by_pos": { "verb": 1 } }
}
```

### Script References

All `python scripts/*.py` invocations in SKILL.md are replaced with the corresponding MCP tool call. The tool names, input parameters, and output fields map 1:1 to the existing CLI interfaces.

## Plugin Integration

### .mcp.json (at plugin root)

```json
{
  "mcpServers": {
    "claude-of-alexandria-mcp": {
      "command": "node",
      "args": ["${CLAUDE_PLUGIN_ROOT}/servers/claude-of-alexandria-mcp/dist/index.js"],
      "env": {
        "DATA_DIR": "${CLAUDE_PLUGIN_ROOT}/servers/claude-of-alexandria-mcp/data"
      }
    }
  }
}
```

When the plugin is installed in Claude Code, the MCP server starts automatically. No user configuration needed.

### Claude Desktop Configuration

Users add to their MCP settings:

```json
{
  "mcpServers": {
    "claude-of-alexandria-mcp": {
      "command": "npx",
      "args": ["-y", "claude-of-alexandria-mcp"]
    }
  }
}
```

One line. npm handles download, caching, and execution.

## Distribution

| Channel | Mechanism | User Action |
|---------|-----------|-------------|
| Claude Code plugin | `.mcp.json` bundled in plugin, server in `servers/` | Install plugin; server auto-starts |
| Claude Desktop | `npx claude-of-alexandria-mcp` | Add one entry to MCP settings |
| npm | `npm install -g claude-of-alexandria-mcp` | Alternative global install |

### npm Package Contents

The published npm package includes:
- Compiled TypeScript (`dist/`)
- SQLite database (`data/biblical.sqlite`)
- No source JSON/YAML (those stay in the git repo)

### Build Pipeline

```bash
# In servers/claude-of-alexandria-mcp/
npm run build:db      # JSON/YAML → SQLite (reads from ../../plugins/.../reference/)
npm run build         # TypeScript → JavaScript
npm run prepublish    # build:db + build (runs before npm publish)
```

## Migration Plan

### Phase 1: Build MCP Server
1. Initialize TypeScript project in `servers/claude-of-alexandria-mcp/`
2. Implement `build-db.ts` — read all reference JSON/YAML, write SQLite
3. Implement four tool handlers mirroring Python parser interfaces
4. Test each tool against Python script output for parity

### Phase 2: Integrate with Plugin
5. Add `.mcp.json` to plugin root
6. Update SKILL.md — replace `python scripts/*.py` with MCP tool calls
7. Update `allowed-tools` in SKILL.md and command files
8. Test end-to-end in Claude Code

### Phase 3: Publish & Distribute
9. Publish to npm as `claude-of-alexandria-mcp`
10. Update `package-desktop.yml` workflow (skill ZIPs no longer need data exclusions)
11. Update README with Desktop installation instructions
12. Update CHANGELOG

### Phase 4: Cleanup
13. Mark Python scripts as archived/reference (don't delete — they document the data format)
14. Consider removing large JSON/YAML from skill ZIP (data now in SQLite)

| Small YAML refs (book-genres, etc.) | **Stay** — still directly referenced by SKILL.md |

## Risks

| Risk | Mitigation |
|------|------------|
| SQLite size exceeds npm publish limit | npm allows up to 1GB; 40MB estimate is well within |
| Output parity with Python scripts | Test each tool against Python output before migration |
| better-sqlite3 native module issues on some platforms | Use sql.js (pure WASM) as fallback, or prebuild binaries |
| MCP server startup latency | SQLite is fast; cold start is sub-second |
| Desktop users don't know to install MCP server | README instructions + skill output notes when tools unavailable |

## Success Criteria

- [ ] All four MCP tools return identical data to their Python equivalents
- [ ] Skill works end-to-end on Claude Code via plugin-bundled server
- [ ] Skill works end-to-end on Claude Desktop via `npx` server
- [ ] Skill ZIP under 30MB (no data exclusion hacks needed)
- [ ] npm package published and installable
- [ ] SKILL.md references MCP tools, not Python scripts
